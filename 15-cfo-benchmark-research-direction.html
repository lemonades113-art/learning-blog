CFO-Bench 研究方向调整：从会议决策到论文路线图

本文把 2026 年 11 月 4 日的 CFO 研究会议与现有《CFO-Bench 1.0》放在一起，回答四个问题：老师实际安排了什么；论文应该讲一个什么故事；DAG、有效工作节点、真实单据和 SIMECO 应该放在哪里；接下来怎样把研究问题、贡献和实验逐步做实。

核心判断：论文当前应以“企业内部财务工作 Agent Benchmark”为主线，先说明为什么需要这样的 Benchmark、现有工作缺什么、我们如何构建和评估，再用实验说明它测出了什么。决策关键依赖 DAG 保留为任务结构化与专业判断分析方法，不能在缺少实现和实验的情况下直接把它写成已经成立的核心创新。
主线：CFO Work Benchmark方法候选：有效节点 + 专业依赖 DAG待补证据：真实单据、专家校准、100 题结果

一、会议究竟安排了什么？先把三条工作线分开

这次会议同时谈了研究论文、金融训练数据合成和真实单据验收。如果把它们混成一件事，就会误以为论文要把所有工程工作都写进去。实际分工是：论文负责提出研究问题、比较已有工作、解释方法和验证贡献；训练数据合成负责形成业务数据资产；真实单据验收负责提高后续合成材料的真实性。

当前三条工作线
A · CFO-Bench 研究论文
研究问题 / Related Work / 方法 / 实验
+
B · 金融训练数据合成
与丽佳协作 / 专业性把关 / 抽样质检
+
C · 真实单据采购验收
供应商交付 / 样本检查 / 模板校准
三条线共享金融专业知识和数据资产，但交付目标不同。论文不能把业务执行清单原样搬进正文。

1. CFO-Bench 研究论文：你的核心研究责任

老师希望你先做 Related Work，找到直接相关的财务 Benchmark 和企业工作流评测，逐篇看它们怎样写研究动机、任务设计和贡献，再回答 CFO-Bench 与它们的差异。你需要负责研究故事、贡献论证、论文结构和实验方案；后续也可以与前期参与构建的同学共同完成论文。

2. 金融训练数据合成：丽佳负责工程，你把专业方向控住

老师提出与丽佳一起推进新版本金融数据合成。她可以负责主要工程生产，你负责从金融专业角度检查题面是否真实、业务逻辑是否成立、考点和错误点是否合理，并用 AI 辅助检查。需要向前期做过 CFO 版本的同学及金融群成员了解新合成链路的变化。

3. 真实单据采购验收：等材料和标准到位后执行

供应商将陆续交付约百余份单据样本。老师会补充验收文档，你按验收标准抽样检查单据真实性、字段、版式和业务关系。采购来的真实样本还可能用于重新校准合成模板，并作为论文中数据构建真实性的一项证据。

4. 金融多轮 Benchmark：暂时作为独立收尾事项

会议中提到当前约 20 多道题，模型分数大致在 40–60 分区间，千问略低于 GPT。但老师也指出题目经过质检和修改后可能需要重新运行。因此现有分数是阶段性结果，不能直接作为最终论文实验结论，也不应与 CFO-Bench 混成一个 Benchmark。

关键边界：金融多轮评测、CFO Work Benchmark、金融训练数据是不同产品或数据用途。可以复用底层金融知识和部分工程能力，但必须分别说明任务对象、数据划分和评测目标。

二、论文主线为什么要调整？从 DAG-first 改为 Benchmark-first

此前研究方案把“决策关键依赖 DAG → 受控干预 → 材料传播 → 独立 Golden → Claim 评分 → 匹配实验”放在最前面，容易把整篇论文写成一篇 DAG 任务生成方法论文。老师本次会议给出的组织顺序更明确：先确定 Benchmark 的研究对象和现有缺口，再讲我们怎样构建，最后展示评分与实验。

建议采用的论文主线
研究背景
企业 Agent 要完成真实财务工作
↓
现有研究缺口
内部数据 / 凭证级材料 / 专业判断 / 长程任务
↓
构建方案
SIMECO/VEA + 专家辅助 AI + 真实单据模板校准
↓

↓

这条主线先回答“为什么需要这个 Benchmark”，再回答“我们做了什么”和“它是否有效”。它能容纳现有 SIMECO、任务合成、DAG、Oracle 和 Rubric 资产，又不会让论文变成内部系统模块清单。

此前 DAG 方案如何保留？

此前内容调整后的位置论文中承担的作用
决策关键依赖 DAG任务结构化方法 / Method 子节描述专业判断之间的必要依赖
Evidence → Judgment → Claim任务定义与评分设计把业务材料、判断和交付字段连起来
关键条件干预难度控制与实验分析检验业务条件变化是否引起预期决策变化
Oracle 独立复算Reference / Ground Truth避免直接把生成器隐藏状态当答案
Claim 级 RubricEvaluation Protocol判断工作产物中的关键字段和结论是否正确
匹配实验Experiments区分专业判断难度与单纯材料规模

因此，DAG 仍然重要，但它应当服务于 CFO-Bench 的研究问题，而不是先验地决定整篇论文必须成为 DAG 论文。

三、CFO-Bench 1.0 已经有什么？先看现有资产，再谈创新

现有 CFO-Bench 文档将研究对象定义为 CFO 团队日常岗位任务，覆盖业财转分录、费用预审、发票匹配、增值税申报、银企对账、资金头寸、流动性预警和内控异常探查等工作。它希望评测 Agent 在跨表、跨期、多步任务中的端到端工作能力。

领域代表工作典型专业问题
财务分录、费用、发票、应收、月末关账科目错置、三单不匹配、坏账计提不足
税务增值税申报、关联交易、转移定价四流不一致、关联方隐匿、利润转移
财资银企对账、资金头寸、流动性、融资受限资金、余额粉饰、契约违约
内控异常探查、风险监控虚假付款、拆单规避审批、复合异常

现有资产可以归纳成四层

1. 企业数据层

合成 ERP 账套、凭证、单据、流水、报表、员工和业务实体；文档描述的样本规模包括 45+ Sheet、1100+ 凭证、700+ 员工。

2. 专业场景层

财务、税务、财资、内控等岗位场景；每个场景定义业务目标、任务数据、违规埋点、外部数据和 Agent 交付物。

3. 任务生产层

专家制定场景标准，Producer Agent 生产题源和答源，提取 Rubric，执行硬校验、LLM Judge 和专家终审。

4. 评估层

事实准确性、业务规则遵从、专业判断质量，以及任务完整性、长程一致性、表达和惩罚项等评分维度。

这四层是论文可以展开的已有基础。研究不能只列资产名称，还需要说明每层如何支持研究目标，以及有什么独立证据证明它工作正常。

现有文档本身还存在需要统一的口径

检查项当前文档中的不一致需要核实
BDF 数量对比表写 44 类，构建动机写 41 个以实际注入器清单和版本为准
场景数量前文写 17 个岗位场景，后文扩展到 R20–R22区分原始版本与扩展版本
交付率写 18/20=90%，样板任务表列出 19 个 pass统一统计分母、场景状态和样板任务口径
R17 状态一处写待 v3，另一处写已交付且 pass核对最新任务包和版本
模型成绩会议提到后续会提供约 100 题评分版本关联题目版本、模型版本和评分版本
这些是当前文档的口径审计问题，不代表底层工程一定错误。论文统计必须以冻结后的任务清单、生成记录和评分结果为准，不能直接复制旧文档中的数字。

四、本次会议新增的三个研究机会

机会一：真实单据模板校准

老师提出采购真实单据样本，后续用真实样本重新对齐合成模板。它能补充合成材料的真实性证据：字段、版式、业务表达和单据之间的关系更接近真实企业工作。研究时应比较模板校准前后的字段覆盖、格式分布、业务关系和专家真实性判断，而不是只说“我们采购了真实单据”。

机会二：新版 SIMECO 的业务复杂性

老师提到新版 SIMECO 可以合成更多类型的账表，合成链路也更复杂。这为扩大场景和材料类型提供了机会，但必须拿新旧版本的实际样本做比较，说明增加了哪些实体、单据、业务关系、状态或专业判断。仅凭会议描述，暂时不能写成已验证的能力提升。

机会三：专家辅助 AI 的任务生产机制

现有文档已经描述专家定义标准、AI 生产题源和答源、Rubric 提取、Verifier 自检、Judge 与专家终审的链路。论文可以把它概括为 Expert-guided AI Benchmark Construction。需要补充专家究竟制定了哪些专业规则、审查了哪些输出、发现了哪些问题、修复率如何，以及专家与自动检查分别承担什么责任。

内容目前证据状态论文写法
原有 SIMECO/VEA 合成体系已有文档描述介绍现有数据构建方案，并核对实际产物
新版 SIMECO 更复杂会议提出，待验证先做新旧版本能力对照
采购真实单据已提出采购，待交付暂时写成计划，不写成已完成
真实模板校准后续工作完成后报告校准方法和效果
专家辅助 AI 构题已有流程设计，细节待补补专家参与记录和质量证据

五、有效工作节点与 DAG 应该怎样放？

老师在会议中提出：去掉重复工作步骤后，保留下来的有效工作节点和工作环节可以用于定义长程任务，再根据有效链路长度判断任务是否属于长程。这是一个值得发展的任务复杂度定义，但还需要明确“有效”如何判定。

5.1 什么叫有效工作节点？

一个有效工作节点应当代表一项独立、必要、能影响后续工作或最终交付的业务操作或专业判断。把它删除后，任务会出现必要证据缺失、判断无法成立、计算无法完成、控制条件未检查或交付物不完整等问题。重复读取、纯格式转换、没有独立业务作用的机械步骤不应重复计数。

示例：月末关账中的必要工作节点
读取银行流水
→
核对企业账簿
→
识别期末异常资金
↓
检查期后回转
→
判断资金真实性
→
形成关账意见
这是用于解释的简化示意，不是已经冻结的正式任务节点数。正式节点需要由 TaskSpec、材料和专家判断共同确定。

5.2 长程任务不能只按节点数量定义

候选指标定义能回答什么
Effective Node Count去重后独立且必要的业务节点数量任务包含多少项真实工作
Dependency Depth从初始证据到最终交付的最长必要依赖路径完成任务需要连续经过多少层依赖
Cross-source Integration必须联合使用的独立数据源及其关系任务是否需要跨文件、跨系统核对
State / Temporal Dependency前序事件或期间状态对后续判断的约束任务是否需要跨期追踪和状态更新

例如，一个任务可能有 20 个并行节点，却只有 3 层依赖；另一个任务只有 8 个节点，却有很长的连续判断链。因此节点数量和依赖深度必须分开统计。

5.3 DAG 在这里具体负责什么？

DAG 把任务里的证据、规则、判断、计算、控制和输出连接起来。它帮助我们判断哪些节点真正必要、哪些节点依赖前序条件、哪些判断会影响最终工作产物。

任务内部的专业依赖图
Evidence
合同 / 单据 / 流水
→
Rule / Condition
生效期 / 阈值 / 例外
↓
Judgment
主体 / 期间 / 业务性质
→
Computation / Gate
金额 / 勾稽 / 审批
↓
Output Claim
工作产物字段 / 结论 / 处理决定

此前提出的“决策关键依赖”仍可作为进一步研究：改变某项必要业务事实，预期哪些判断、计算和输出字段应发生变化？这可以通过受控变体和独立 Golden 验证。

有效工作节点

回答“这项工作是否真的必要？”可用于任务复杂度和长程性定义。

决策关键依赖

回答“改变这项业务条件，会影响哪些后续判断和交付？”可用于干预设计和错误归因。

两者有关联，但不能混为一个指标。前者描述工作结构，后者描述业务条件与决策结果之间的依赖关系。DAG 是表达这两类关系的工具，不是自动成立的创新点。

六、研究贡献怎样成立？把“我们做了什么”变成“我们证明了什么”

论文贡献不能靠模块数量堆出来，也不能为了显得创新而夸大。最稳妥的做法是把候选贡献和所需证据一一对应。

候选贡献要回答的研究问题必须提供的证据
C1 · 企业内部财务工作 Benchmark为什么需要专门的 CFO Agent Benchmark？Related Work 对比、任务覆盖、真实业务工作流说明
C2 · 专业任务数据构建无法公开真实企业账套时，怎样构造可信且可复现的任务材料？SIMECO 数据链、真实单据模板校准、专家验收和复现记录
C3 · 长程专业工作测量怎样区分真实业务依赖与单纯步骤数量？有效节点、依赖深度、跨源整合、跨期状态指标及专家复核
C4 · 专业能力评分怎样判断 Agent 是否真正完成专业工作？独立 Golden、Claim/Rubric、评分夹具、专家一致性
C5 · 模型能力分析当前模型在哪些工作环节和专业判断上失败？逐题结果、错误归因、不同模型和任务类型的比较

这些是候选贡献，不代表最终必须写成五项独立创新。更可能的组合是：以 CFO-Bench 作为整体贡献，以可信专业任务构建和长程工作测量作为核心设计，以专业评分与模型分析提供有效性证据。

建议的研究问题：如何可靠地评估 AI Agent 在企业内部复杂财务环境中完成长程专业工作的能力，尤其是在内部业务数据难以公开、专业判断不可省略、最终工作产物必须可验证的情况下？

贡献表述的三个证据等级

阶段可以怎么说不能怎么说
研究设计阶段我们设计了……，拟通过实验检验……我们证明了……
工程实现阶段我们实现了……，并在指定任务范围内通过……已形成普遍适用的方法
实验验证阶段在冻结任务集和指定模型上，实验结果表明……把有限样本结果推广为所有企业 Agent 的结论

七、实验需要什么证据？100 道题不能只给平均分

老师提到后续会提供一版约 100 题的评分数据。拿到之后，第一件事不是马上写“模型 A 比模型 B 强”，而是先核对题目版本、领域覆盖、评分口径和模型运行是否一致。

7.1 100 题结果至少需要六类分析

  1. 总体表现：模型均分、分布、通过率、零分或异常任务数。
  2. 领域表现：财务、税务、财资、内控分别表现如何。
  3. 工作类型表现：对账、复算、审批、异常识别、资金决策等任务差异。
  4. 长程性表现：有效节点数、依赖深度、跨源整合和跨期状态与成绩的关系。
  5. 错误归因：事实错误、规则错误、专业判断错误、遗漏交付、证据不足、越权动作。
  6. 评分可靠性：Golden 是否独立复算，Rubric 是否接受合理替代答案，Judge 与专家是否一致。

7.2 推荐的实验结果表

关键依赖实验基础任务与关键条件变体预期变化正确率、下游 Claim 一致性Agent 是否理解业务条件变化的后果
评分校准Judge 与专家盲审一致率、假接受、假拒绝、争议率分数能否代表真实工作质量
数据真实性模板校准前后合成样本字段覆盖、格式差异、专家真实性判断真实模板是否提高材料可信度

7.3 DAG 匹配实验如何作为深化研究

如果后续希望把 DAG 做成方法贡献，可以设计基线、结构扩展、关键条件干预、无关干扰和语义等价五组任务。保持题族、交付目标和运行预算尽量一致，比较模型是否只被更多材料拖慢，还是确实在关键专业判断上发生错误。所有受影响材料都要同步更新，Oracle 从考生可见材料独立复算 Golden；否则变体本身可能变成矛盾题。

DAG 实验是候选深化方向，不是当前已完成的实验结果。若 100 题数据不包含受控变体和逐项 Claim 证据，就不能仅凭总分证明“决策关键依赖 DAG”有效。

八、论文每一部分具体写什么？先把骨架搭起来

论文部分要回答的问题应写的关键内容核心图表
1. Introduction为什么要做？企业 Agent 的工作需求、内部财务数据难题、已有 Benchmark 缺口、本文方案和贡献研究动机图、贡献列表
2. Related Work别人做到了什么？财务 Benchmark、企业工作流、ERP/环境、数据合成、专业评分竞品对照表、文献技术节点图
3. Benchmark Design我们评什么？CFO 岗位范围、四大领域、任务定义、输入材料、交付物、长程性定义Benchmark 总览图、任务覆盖表
4. Data Construction题目怎么来？SIMECO/VEA、合成账套、单据模板、业务事件、违规埋点、专家辅助 AI、质量门数据生产链路图、样本示例
5. Evaluation Protocol怎么判对错？Golden、Verifier、Rubric、Claim、Judge、专家校准、UNKNOWN 处理评分架构图、Rubric 示例
6. Experiments模型表现如何？模型、设置、总体结果、分领域结果、长程性和难度分析模型结果表、分布图
7. Error Analysis模型具体哪里失败？专业错误、证据遗漏、跨表失败、状态错误、合理替代答案错误分类图、案例分析
8. Limitations结论边界是什么？合成数据代表性、专家范围、任务覆盖、模拟与真实部署差异局限性与未来工作

这就是论文的填充顺序：先把 Introduction 和 Related Work 的研究问题定下来，再冻结 Benchmark 的对象与口径，然后补齐数据和评分证据，最后根据实验结果写结论。不要先把所有工程模块写完，再试图从里面找一个故事。

九、怎样逐篇精读论文？每篇都要读到研究故事和实验机制

老师特别要求精读优秀论文，尤其是 Introduction。之后不应只输出摘要，而应还原作者从研究问题到实验结论的完整过程。

阅读层每篇必须回答的问题
1. 研究问题作者到底想解决什么？研究对象和核心矛盾是什么？
2. Related Work已有研究做到了什么？作者认为缺口在哪里？
3. 任务与数据数据来源、规模、输入形式、任务构造和划分是什么？
4. 核心方法每个模块的输入、处理、输出是什么？模块如何连接？
5. 技术细节算法、公式、模型、Prompt、环境、约束和参数是什么？
6. 评测协议Golden、Metric、Judge、人工评审、对照组和消融如何设计？
7. 实验结果逐表逐图说明数字，提升幅度、基线、统计证据和失败样本是什么？
8. 局限性作者明确承认什么？实验还不能支持什么？
9. 对 CFO 的关系哪些机制可借鉴，哪些已有先例，哪些差异仍需证明？
10. 对论文的影响读完后是否改变研究动机、任务定义、方法、指标或实验？

阅读资源分层

  • 核心竞争论文 4–6 篇：全文精读，包含方法、实验、附录和可用代码。
  • 直接相关论文 8–12 篇：重点读 Introduction、Method、Experiments 和 Limitations。
  • 扩展研究 10–20 篇：判断技术先例、研究边界和潜在借鉴点。

每篇精读都应形成两份结果：一份是忠实于原文的论文机制复原；另一份是与 CFO-Bench 的逐项映射。不能把模型推断、作者原文和我们自己的研究设想混在一起。英文原文仍需要自己读，AI 用于陪读、解释和交叉核对。

十、下一步行动与待确认问题

第一优先级：论文研究

  1. 找回老师提到的 7 月 Related Work 表格和对应论文链接。
  2. 核对老师提到的 CFA 论文具体是哪一篇，避免只凭缩写判断。
  3. 选出 4–6 篇最直接的竞争论文，优先精读 Introduction、Method 和 Experiments。
  4. 制作统一对比表：研究对象、数据、任务、环境、长程定义、专业能力、评分、模型结果、局限。
  5. 基于证据形成 CFO-Bench 的差异点和贡献候选。

第二优先级：金融训练数据合成协作

  1. 获取新版 SIMECO 和合成链路文档。
  2. 与丽佳确定题目生产、专业审查和修改反馈的分工。
  3. 抽取 3–5 个样本，检查题面真实性、业务逻辑、专业考点、Golden 和难度。
  4. 把发现的问题写成可执行修改意见，而不是只给“好/不好”的判断。

第三优先级：真实单据验收准备

  1. 等待采购交付和正式验收规范。
  2. 按单据类型检查字段、版式、完整性、业务关系和可用于模板校准的程度。
  3. 记录样本来源、版本、脱敏情况和验收结论。

第四优先级：100 题评分分析

  1. 获取冻结题目清单、版本和逐题模型结果。
  2. 核对模型版本、运行配置、Rubric 版本和异常运行。
  3. 先做领域、工作类型、有效节点和依赖深度分布。
  4. 再做错误归因和专家评分校准。
需要向老师确认的一个关键问题：会议中提到希望千问训练数据能让千问表现较差、最好三四十分，但训练数据和评测数据的目标不同。需要确认这批数据究竟是训练集、训练诊断集还是独立评测集。如果用于训练，应该看训练前后独立留出集的变化；如果用于评测，应该保证任务公平、可解、评分可靠，不能人为追求低分。

十一、当前结论与证据边界

目前最稳妥的论文定位：面向企业内部财务工作的长程 Agent Benchmark。核心叙事是内部专业工作难以被现有公开数据和通用办公任务充分覆盖，因此需要构建具有真实业务材料、专业判断和可验证工作产物的评测集；通过合成账套、专家辅助 AI、真实单据模板校准和多层评分协议，形成可复现的 CFO 工作评测，并通过模型实验分析能力边界。

有效工作节点和专业依赖 DAG 是这条主线中的重要方法资产：有效节点帮助定义任务的真实工作量和长程结构；DAG 帮助表达证据、判断、规则和交付物之间的依赖；Claim 和 Golden 则把这些判断转化为可检查的评分对象。是否能进一步形成独立的方法贡献，需要受控变体、独立复算和跨任务实验来证明。

因此，当前不应宣称“DAG 方法已经证明提升了专业能力测量”，也不应把新 SIMECO、真实单据校准和 100 题正式结果写成已完成。下一阶段要做的是补齐 Related Work、统一 CFO-Bench 版本口径、核实新数据链路、验收真实单据、冻结任务和评分版本，并对模型结果做逐题分析。
